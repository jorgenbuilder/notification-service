# Cloudflare Worker: notification-collector

Cloudflare Worker that periodically polls the Internet Computer notification canister and dispatches Web Push notifications to browser clients.

It uses a static Ed25519 identity (principal) to authenticate as the `worker` principal configured in your Motoko canister. It calls `isQueueEmpty` (query) and, if there are items, calls `collect` (update) to pull a batch and send them via Web Push using VAPID.

## Features
- Runs on a cron schedule (default: every minute) via `wrangler` triggers.
- Uses `@dfinity/agent` with a static Ed25519 identity.
- Calls canister methods: `isQueueEmpty` and `collect`.
- Sends push notifications using `@block65/webcrypto-web-push` (Workers-native, no Node polyfills).
- Optional HTTP endpoint `/run` to trigger manually.

## Files
- `wrangler.toml` — Worker configuration, cron, and environment variables.
- `src/index.ts` — Worker implementation.
- `package.json` — Dependencies and scripts.
- `tsconfig.json` — TypeScript configuration.

## Prerequisites
- Node.js 18+ (for local builds)
- Cloudflare `wrangler` CLI
- A deployed IC canister with the Motoko code at `src/notification-canister/main.mo` and the `worker` principal set to the Worker’s principal.

## 1) Generate a static identity for the Worker
You need a fixed Ed25519 key to be used by the Worker so its principal matches the `worker` argument used when deploying the canister.

Run command:
```
sh scripts/key.js
```

- Save the `principal` output; deploy your canister with this `worker` principal.
- Save the `secret_base64` output; you’ll set it as a Wrangler secret `WORKER_ED25519_SECRET_KEY`.

## 2) Deploy/upgrade the canister with the Worker principal
Your Motoko canister constructor is:
```motoko
persistent actor class NotificationCanister(worker : Principal)
```
Deploy with proper init args so `worker` equals the Worker’s principal:
```bash
# Example (adjust principals)
dfx deploy notification_canister --argument '(principal "<worker_principal>")'
```

Note: This repository’s `dfx.json` does not include init args — pass them at deploy or via a candid file.

## 3) Configure the Worker
Edit `wrangler.toml` if needed:
- `IC_HOST` — endpoint for IC agent. For local: `http://127.0.0.1:4943`. For mainnet: `https://icp-api.io` (or boundary).
- `NOTIFICATION_CANISTER_ID` — set to your deployed canister ID.
- Cron schedule is under `[triggers].crons`.

Set secrets via Wrangler:
```bash
cd worker-cloudflare
# IC identity secret (base64 of 32 or 64 bytes)
wrangler secret put WORKER_ED25519_SECRET_KEY
```

For local dev, you can export `NOTIFICATION_CANISTER_ID` quickly from `.env` generated by `dfx deploy`.

## 4) Run locally (against local replica)
Start local replica and deploy canisters:
```bash
dfx start --clean --background
dfx deploy
```

Update Worker config:
- `IC_HOST = "http://127.0.0.1:4943"`
- `NOTIFICATION_CANISTER_ID = "$(dfx canister id notification_canister)"`

Then run the Worker:
```bash
cd worker-cloudflare
npm i
npm run dev
```

Trigger manually:
```bash
curl http://127.0.0.1:8787/run
```

## 5) Deploy to Cloudflare
```bash
cd worker-cloudflare
npm i
npm run deploy
```

## 6) Implementation notes
- The Worker uses `@dfinity/agent` to create an `HttpAgent` with its Ed25519 identity. For local replica (`http://127.0.0.1:4943`), it calls `fetchRootKey()`.
- It checks `isQueueEmpty()`; if false, it calls `collect()` which returns up to 100 notifications. Those are sent via `web-push`.
- The payload currently contains `{ title, body }` extracted from `Notification` (`content` -> `body`). Adjust as needed.
- Cron schedule is configured to run every minute. Increase/decrease depending on throughput.

## 7) Web Push compatibility
`web-push` is used for convenience. In most cases it works under Workers with `nodejs_compat`, but if you hit compatibility issues, consider:
- Using native Fetch-based Web Push with manual payload encryption (Web Push protocol: RFC 8291, 8292),
- Or running this collector in a Node/Service environment instead of Workers.

## 8) Security considerations
- Never commit your secret keys. Use Wrangler secrets.
- Ensure CORS/route restrictions if you expose the `/run` endpoint publicly (or disable it).
- Only the Worker principal should be authorized as `worker` in the canister. The canister already asserts caller for `isQueueEmpty` and `collect`.
